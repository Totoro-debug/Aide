# Delegate Single-use SubAgents through Explicit Start and Wait

Foreground and Schedule Routers dispatch bounded tasks to persistent Workers. A Worker can delegate independent, single-use tasks to SubAgents to preserve its context capacity and execute independent work in parallel. The Built-in Tool `spawn_agent` returns a task identifier and `queued` state after registering a task, before execution starts; `wait_agent` blocks to obtain execution results. Separating submission from execution and result collection lets the Worker continue after submitting work even when execution capacity is occupied.

SubAgent execution belongs to its originating Conversation Session and Worker, and may continue in the background after its creating Worker segment finishes. Neither runtime control nor prompt instructions require the Worker to call `wait_agent` or await its SubAgents before finishing. Each Session owns a separate pool with eight execution slots, queues excess tasks, and admits queued work as slots become free. A Worker can obtain its SubAgent results; the Router receives only the Worker report and does not consume SubAgent results directly. `list_agents` exposes brief Session-scoped task information; `wait_agent` can wait for multiple SubAgents and returns a list of terminal results when any reaches a terminal outcome, with one element per SubAgent result. Each result contains task identity, terminal status, final response, error information, and usage rather than its full exchanges. An optional wait timeout ends only that wait and leaves the SubAgents running. Cancellation is a user-facing service operation, rather than a model Tool. Completion updates the Web task list; foreground result delivery and automatic continuation follow [ADR-0034](0034-own-foreground-questions-and-continuations-with-the-session.md).

Each SubAgent has its own model context without copying its Worker's conversation history. The Worker supplies the delegated task and information needed to perform it. A SubAgent inherits its Worker's Workspace, captured model and reasoning effort, permissions, base System Prompt, and Tool capabilities, with `spawn_agent`, `wait_agent`, and `schedule` removed from its Tool Catalog. Parent Conversation Summary, Action Summary, and Blackboard are excluded. This makes delegation non-recursive, prevents a SubAgent from occupying a pool slot while waiting for queued siblings, and keeps Schedule management with the Router and Worker execution paths. Removing Catalog membership, rather than hiding Tool schemas, enforces the boundary described in [ADR-0020](0020-expose-configured-mcp-tools-through-tool-gateway.md).

Tool Confirmations retain the creating Worker's foreground or Schedule origin and queue priority. Each SubAgent owns its confirmation identity and source routing independently of whether its creating Worker segment is still active or its Session still has a Client Claim.

SubAgent output, Tool activity, and terminal results are persisted as Session-associated records. Their full execution histories remain separate from the Worker's model context. Workers and SubAgents share the Workspace without a guarantee that their file modifications are independent. Eligible foreground SubAgent file modifications belong to the creating input's Restore Anchor, so its File Restore includes those modifications under the existing restoration rules.

SubAgent context budgeting follows the existing budget and compaction rules, while compaction summaries and state remain in the SubAgent's own records and never enter the Workspace `memory/summary.jsonl` stream. Usage is recorded per Router, Worker, and SubAgent; the Router's projected context occupancy uses only its own model requests.

Releasing a Session Claim or switching conversations leaves SubAgents running. Session Restore and deletion are busy while the Session has queued or running SubAgents. Restore removes the SubAgent Conversations and results created by the discarded foreground inputs while retaining earlier ones; Session deletion removes all its SubAgent records. Removing a user Schedule Job cancels the outstanding SubAgents it created; removing a Project cancels and drains all of its Workspace's SubAgents. Service shutdown cancels and drains outstanding tasks, retains their interrupted records, and does not resume them automatically on restart. This keeps delegated execution within the existing Runtime Lifetime while allowing execution to outlive individual Main Agent Runs.

Single-use tasks and explicit context handoff avoid introducing a second conversational relationship for follow-up messages and prevent delegation from automatically duplicating the parent transcript. Run-local capabilities and inherited snapshots follow [ADR-0026](0026-tool-permission-levels-and-foreground-snapshots.md) and [ADR-0029](0029-host-cli-and-web-through-one-local-service.md).
