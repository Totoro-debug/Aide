# Keep Foreground Questions and Continuations with the Session

Foreground Tasks need to retain unanswered Human Questions and Worker reports after a Router Run ends or its Client switches conversations. Keep their durable coordination with the owning Conversation Session, separate from Client Claims, the Blackboard's semantic task definition, and transient presentation events. Use versioned Workspace-owned files under the existing file-first policy; retain existing Session, Worker, and SubAgent records as their respective authorities. Cross-file publication requires recoverable intents and reconciliation, rather than an assumed shared transaction or a claim of exactly-once external effects.

A Human Question is an information request, not permission to execute a Tool. Give questions their own answer operation, restricted to the current Session Claim. Finish the question Tool exchange and suspend execution at a complete ReAct boundary instead of retaining an awaiting coroutine or an unmatched Tool call. Resume with an explicit answer and saved conversation context; never replay completed Tools or persist a Provider's opaque ModelContinuation. This releases the Session processor and SubAgent capacity while retaining questions independently of context compaction.

Retain the originating execution role with the Foreground Task. Router answers, explicit continuations, and recovered segments inherit its restricted Tool Catalog; the trigger for a new segment cannot grant Agent capabilities. Records predating this role retain their original Agent behavior. A Router `finish` response is projected into a separate assistant message with its source Tool call and zero additional Model usage, so the answer survives reload without counting another Model request. It has no Provider usage provenance; subsequent budgeting follows the complete-estimate fallback in [ADR-0023](0023-manage-agent-run-context-by-projected-token-budget.md).

SubAgent completion events wake the owning Worker, and Worker reports wake the Session arbiter. Persisted terminal records and delivery receipts determine whether results need handling; explicit wait delivery and automatic delivery share the same receipt. Prefer queued user input before starting a Router continuation, coalesce currently available Worker reports, and allow at most one Router execution per Session. Automatic execution retains the originating foreground authorization ceiling and never falls back to Schedule permissions when a Claim is absent. Cancelling or replacing a Task fences its late callbacks. Restore and deletion fence the same coordination before changing Session authority.

When a Worker segment ends with owned SubAgents that are unfinished or whose results have not been read, persist a waiting segment and do not publish a ready report. A terminal child event records only its identity, status, and revision for the Worker to inspect; the Worker calls `wait_agent` to read the result before completing its report. Router completion checks apply to both ordinary final text and `finish`: any report still owed to the current Task suspends the Router, and the durable final answer is committed only after the required reports have been delivered.

Foreground Router Tasks may dispatch independent Workers concurrently and wait without retaining the Router execution. Each Worker retains its captured execution resources until it stops. Once all assigned Workers have terminal reports, the same Session arbiter claims their unconsumed reports in one atomic batch after queued user input. A durable Router completion or complete suspension boundary records the batch receipts; reconciliation repairs interrupted receipt indexing before another delivery. A later dispatch receives only new reports. Cancellation and replacement fence the Task generation, while restart preserves reports and requires explicit user continuation of interrupted work. CLI and Web project the same Router role, parent Task, Worker identifiers, generation, and status from Session state.

Separate a Task's logical origin from each execution segment's side-effect ownership. A Human Answer or explicit continuation is a real user operation with its own Restore Anchor; automatic segments inherit the applicable user operation rather than inventing a user message. SubAgent segment snapshots and file journals must follow these anchors. Extend the durable Restore transaction to restore the retained execution prefix and invalidate discarded questions, answers, and result receipts; merely deleting SubAgents by their original source token would miss changes made after an answer.

Web, CLI, and user Schedule occurrences enter the Router path. Workers may use the existing Schedule capability and manage their own SubAgents; each resulting occurrence is a new Router input tied to its persisted occurrence identity. A Client switching conversations does not end foreground work while the service has online Clients. Service shutdown follows the current on-demand lifetime; startup exposes saved questions and interrupted work but does not execute it until a person answers or explicitly continues.

Session navigation entries expose a count-only Foreground Attention Summary: total Human Questions, Router/Worker and SubAgent counts, and interrupted Foreground Tasks without unresolved questions. They omit question text and are read from the owning Workspace's persisted coordination state. Web refreshes this summary when the service requires a state snapshot; CLI shows the same counts in `/resume`. Opening a Session under its current Claim loads the full question and task state, so summary visibility does not grant answer or task-operation authority.

This supersedes the explicit-wait-only choice in [ADR-0030](0030-delegate-single-use-subagents-through-explicit-start-and-wait.md) and qualifies the relationship between foreground execution and Client Claims in [ADR-0029](0029-host-cli-and-web-through-one-local-service.md). File ownership and Restore boundaries remain grounded in [ADR-0001](0001-file-first-local-persistence.md) and [ADR-0028](0028-session-restore-architecture.md).
